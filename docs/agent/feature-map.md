# Feature Map

Technical reference: start with the [product overview](context.md) and affected product page.
Search this file for the specific implementation contract or selector; do not load it in full
as startup context.

Inspect `[data-studio-state]` for observed room, active thread and project. The stage exposes
`data-stage-view` and `data-selected-run`. These are observations, not state-restoration APIs.
All selectors below are desktop DOM unless the surface column says otherwise. Resolve one
visible enabled target immediately before input; scope repeated Stop/Dismiss/Close controls.
Keyboard shortcuts are renderer-local; delivery while the game owns keyboard focus is unverified.

## Reliability surfaces

- Generated originals, renamed copies and build-workspace availability: `main/game-assets.ts`,
  `shared/game-assets.ts`, `panels/AssetsCanvas.tsx`; Build jobs open their corresponding Assets entry.
- Delivered-file Git continuity: `main/asset-checkpoints.ts`, `StudioCore.api` asset methods,
  director integration preflight. A modified delivered file requires resolution rather than deletion.
- Blender transforms: bundled `transform` and `compose` native recipes; declared inputs, read as
  `ASSET_INPUTS[...]`, stay unchanged; output plus renders capped at 100 MiB.
- Publish upload/readiness: `plugins/genex/deployment.ts`, `entry-page.ts`, adapter and publish
  panel. A publish connects an SDK-less game, tests its draft (revision, files) before promoting
  it, then sends the Genex cover (`cover.ts`); the copy's package.json
  names its SDK, so the CLI sends `embedSdkVersion`.
- Build status, panel and live view: `RunGraph`, `RunInspector`, `run-steps.ts`.
  Total time uses persisted run boundaries. A live run keeps its newest work in view without
  opening anything; panning or zooming stops that and offers Jump to now.

Chat reading hierarchy: neighboring tool calls, reasoning summaries and routine updates share one chronological work disclosure (`[data-work-log]`). Replies, errors, decisions and results stay in reading order. Current workers use quiet rows and the live heading names their running tool. Permission questions use selectable full-row answers, explicit confirmation and collapse/reopen controls; intake questions add an in-place answer row (`[data-question-own]`) and Chat about this (`[data-question-chat]`). Plans appear expanded in `[data-plan-review]`: `[data-plan-body]` scrolls while `[data-plan-actions]` keeps Approve, Make changes and Cancel visible. Make changes focuses the PromptBar, retains its draft and shows a revision status in chat. Planning uses the current-work status and the timer sits below it. Pending permission remains reachable independently of history pagination; completed screenshots are requested through View screenshots. Background activity never overrides a live conversation reply/tool/waiting phase. `conversation-presentation.test.ts` owns these presentation boundaries; chat UI acceptance exercises them through real input.

### Appearance

`[data-appearance]` inside Settings holds mode previews and independent light/dark editors.
`[aria-label="light theme preset"]` and the dark counterpart open keyboard-accessible menus.
Color inputs accept picker values or committed hex (Enter/blur); invalid drafts do not persist,
and Escape follows normal modal dismissal. Customize theme reveals surfaces, borders, statuses,
contrast and Save as preset. Reset restores one Genex palette; Restore default appearance preserves
saved presets. Mode/overrides/fonts hydrate before React and survive profile reload.
Copy theme emits DTCG sRGB tokens; Import accepts those Genex tokens or mapped VS Code UI JSON/JSONC.
Files are limited to 128 KB and 24 saved presets; includes, invalid colors and wrong-scheme imports
fail without changing the active selection. See [theme formats and sources](../../design/genex/THEMES.md).
Conformance tests, the appearance UI runner and owned fixture captures cover this surface.
Plugin context requests receive current host colors; custom plugin documents own their own styling.

Assets cards show model/texture thumbnails, playable waveforms and video frames; a click opens the viewer. Animation-only GLBs fold into the model whose bones they move (`studio:game.asset.rigs`, `shared/model-rig.ts`), counted in `[data-asset-clips]`. Provenance identifies the producing/transformation tool, never the GLB format. Successful plugin account setup persists restore intent; disconnect prevents restoration.
